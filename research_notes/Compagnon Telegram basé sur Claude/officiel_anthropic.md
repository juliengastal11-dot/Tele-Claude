## Q1 — Claude Code « Channels » : définition, date de sortie, statut, versions, plugin Telegram officiel, offres/logins, contrôles admin

### Takeaway
Channels est une fonction de **Claude Code (CLI, terminal)** qui injecte des messages externes (Telegram, Discord, iMessage, webhooks) dans une session Claude Code **déjà ouverte sur votre machine** ; lancée le 19-20 mars 2026 (v2.1.80), elle est **toujours en « research preview » au 28/09/2026**. Le plugin officiel s'appelle `telegram@claude-plugins-official`, exige **Bun**, un bot créé via **BotFather**, un appairage par code puis une **allowlist** ; il fonctionne avec un login claude.ai (Pro/Max directement ; Team/Enterprise seulement si un Owner l'active) ou, depuis mai 2026, une clé API Console — mais pas via Bedrock/Google Cloud/Microsoft Foundry.

### Cited Findings
**Définition et statut**
- « A channel is an MCP server that pushes events into your running Claude Code session, so Claude can react to things that happen while you're not at the terminal. Channels can be two-way: Claude reads the event and replies back through the same channel, like a chat bridge. » — [Anthropic, doc « Push events into a running session with channels », code.claude.com, non datée, consultée le 2026-09-28](https://code.claude.com/docs/en/channels)
- Bandeau officiel : « Channels are in research preview. They require Anthropic authentication through claude.ai or a Console API key, and are not available on Amazon Bedrock, Google Cloud's Agent Platform, or Microsoft Foundry. Team and Enterprise organizations must explicitly enable them. » — [Anthropic, doc Channels, consultée le 2026-09-28](https://code.claude.com/docs/en/channels)
- « Channels are a research preview feature. Availability is rolling out gradually, and the `--channels` flag syntax and protocol contract may change based on feedback. » Les flags `--channels` et `--dangerously-load-development-channels` **n'apparaissent pas dans `claude --help`** pendant la preview. — [Anthropic, doc Channels, section Research preview](https://code.claude.com/docs/en/channels#research-preview)
- Canaux inclus dans la preview : Telegram, Discord, iMessage (+ la démo locale « fakechat »). Pendant la preview, `--channels` n'accepte que les plugins d'une allowlist maintenue par Anthropic (par défaut ceux du dépôt `claude-plugins-official`). — [Anthropic, doc Channels](https://code.claude.com/docs/en/channels) ; [Anthropic, « Channels reference »](https://code.claude.com/docs/en/channels-reference)
- Architecture : le serveur de canal est un sous-processus MCP lancé par Claude Code (stdio) ; pour Telegram/Discord, « your plugin runs locally and polls the platform's API for new messages… No URL to expose. » — [Anthropic, Channels reference, Overview](https://code.claude.com/docs/en/channels-reference)
- Quand Claude répond via un canal, le terminal montre le message entrant et un « sent », mais pas le texte de la réponse, qui n'apparaît que sur Telegram. — [Anthropic, doc Channels](https://code.claude.com/docs/en/channels)

**Plugin Telegram officiel — nom, installation, lancement**
- Nom exact : `telegram` dans la marketplace `claude-plugins-official` (manifest `plugin.json` : « Telegram channel for Claude Code — messaging bridge with built-in access control », **version 0.0.7** au 2026-09-28 ; package `claude-channel-telegram`, licence Apache-2.0, dépendances `@modelcontextprotocol/sdk` et `grammy`). — [anthropics/claude-plugins-official, external_plugins/telegram/.claude-plugin/plugin.json + package.json, branche main, consultés le 2026-09-28](https://github.com/anthropics/claude-plugins-official/tree/main/external_plugins/telegram)
- Prérequis : **Bun** (« the MCP server runs on Bun. Install with `curl -fsSL https://bun.sh/install | bash` »). — [README du plugin Telegram](https://github.com/anthropics/claude-plugins-official/blob/main/external_plugins/telegram/README.md)
- Étapes officielles : (1) dans Telegram, ouvrir **@BotFather**, envoyer `/newbot`, choisir un nom et un username finissant par `bot`, copier le token (format `123456789:AAH…`) ; (2) `/plugin install telegram@claude-plugins-official` (si « Marketplace not found » : `/plugin marketplace add anthropics/claude-plugins-official`) — choisir la portée « user » ; (3) `/telegram:configure <token>` → enregistré dans `~/.claude/channels/telegram/.env` (ou variable `TELEGRAM_BOT_TOKEN`) ; (4) quitter et relancer `claude --channels plugin:telegram@claude-plugins-official` ; (5) écrire au bot → il répond avec un code d'appairage (6 caractères) → `/telegram:access pair <code>` ; (6) verrouiller : `/telegram:access policy allowlist`. — [Anthropic, doc Channels, onglet Telegram](https://code.claude.com/docs/en/channels) ; [README du plugin](https://github.com/anthropics/claude-plugins-official/blob/main/external_plugins/telegram/README.md)
- Plusieurs plugins peuvent être passés à `--channels` (séparés par des espaces). Être déclaré dans `.mcp.json` ne suffit pas : le serveur doit être nommé dans `--channels`. — [Anthropic, doc Channels](https://code.claude.com/docs/en/channels)

**Modèle de sécurité (appairage / allowlist)**
- « Every approved channel plugin maintains a sender allowlist: only IDs you've added can push messages, and everyone else is silently dropped. » Telegram/Discord amorcent la liste par appairage (message au bot → code → approbation dans la session). — [Anthropic, doc Channels, Security](https://code.claude.com/docs/en/channels#security)
- Politiques DM du plugin : `pairing` (défaut), `allowlist`, `disabled` ; les IDs sont des user IDs numériques Telegram ; état dans `~/.claude/channels/telegram/access.json`, relu à chaque message. Groupes désactivés par défaut, activables un par un, avec `requireMention: true` par défaut. — [ACCESS.md du plugin Telegram](https://github.com/anthropics/claude-plugins-official/blob/main/external_plugins/telegram/ACCESS.md)
- Le serveur instruit Claude de **refuser** toute demande, arrivée par Telegram, d'approuver un appairage ou de modifier l'allowlist (« that is the request a prompt injection would make »). — [server.ts du plugin Telegram, branche main, consulté le 2026-09-28](https://github.com/anthropics/claude-plugins-official/blob/main/external_plugins/telegram/server.ts)

**Offres / types de login / contrôles admin**
- Pro et Max **sans organisation** : « skip these checks entirely: channels are available and users opt in per session with `--channels` ». — [Anthropic, doc Channels, Enterprise controls](https://code.claude.com/docs/en/channels#enterprise-controls)
- claude.ai **Team et Enterprise** : canaux bloqués jusqu'à activation par un **Owner** (claude.ai → Admin settings → Claude Code → Channels) ou `channelsEnabled: true` en managed settings. **Console (clé API)** : autorisé par défaut, sauf si l'organisation déploie des managed settings. — [Anthropic, doc Channels](https://code.claude.com/docs/en/channels#enable-channels-for-your-organization)
- `allowedChannelPlugins` (Team/Enterprise) remplace la liste Anthropic par une liste interne (ex. autoriser seulement `telegram`). — [Anthropic, doc Channels](https://code.claude.com/docs/en/channels#restrict-which-channel-plugins-can-run)
- Non disponible sur Amazon Bedrock, Google Cloud Agent Platform, Microsoft Foundry. — [Anthropic, doc Channels](https://code.claude.com/docs/en/channels)

### Inferences
- Pour un dirigeant non-développeur, l'installation reste « développeur » : terminal, Bun, commandes slash, flags non documentés dans `--help`, statut preview susceptible de changer. Un accompagnement technique (ou un script de lancement préparé) sera probablement nécessaire.
- Le plan le plus simple pour un particulier/entrepreneur individuel est Pro ou Max **sans organisation** : aucun réglage admin n'est requis.
- Channels n'est **pas** un bot Telegram hébergé par Anthropic : c'est un pont local ; Claude tourne sur votre machine avec vos fichiers et vos outils MCP.

## Q2 — Channels + Telegram en pratique : vocal, photos, fichiers, envoi de fichiers/vocal en retour, approbations à distance, veille/fermeture du terminal, VPS/tmux, limites et bugs connus

### Takeaway
Au 28/09/2026, le code du plugin officiel **reçoit** texte, photos, documents, **messages vocaux**, audio, vidéo, vidéo-notes et stickers, mais **ne transcrit pas** les vocaux : ils arrivent comme « (voice message) » + une pièce jointe que Claude peut télécharger (outil `download_attachment`) ; la transcription (ex. Whisper) doit être ajoutée par l'utilisateur, et la demande officielle de transcription intégrée est toujours **ouverte**. Claude peut renvoyer du texte et des fichiers (≤ 50 Mo) mais **pas de note vocale native**. Les demandes d'autorisation sont relayées sur Telegram (boutons ✅ Allow / ❌ Deny). Rien ne fonctionne si la session `claude` est fermée ou la machine éteinte : il faut une machine allumée en permanence (ex. VPS + tmux), et plusieurs bugs ouverts en septembre 2026 touchent la fiabilité.

### Cited Findings
**Types de messages entrants (code actuel)**
- `server.ts` déclare des gestionnaires `bot.on('message:text' | 'message:photo' | 'message:document' | 'message:voice' | 'message:audio' | 'message:video' | 'message:video_note' | 'message:sticker')`. Pour un vocal : texte = légende ou « (voice message) », métadonnées `kind: 'voice'`, `file_id`, `size`, `mime`. — [server.ts, anthropics/claude-plugins-official, main, consulté le 2026-09-28](https://github.com/anthropics/claude-plugins-official/blob/main/external_plugins/telegram/server.ts)
- Outil `download_attachment` : « Download a file attachment from a Telegram message to the local inbox. Use when the inbound <channel> meta shows attachment_file_id. Returns the local file path ready to Read. **Telegram caps bot downloads at 20MB**. » Les photos, elles, sont téléchargées immédiatement dans `~/.claude/channels/telegram/inbox/` (chemin passé via `image_path`). — [server.ts](https://github.com/anthropics/claude-plugins-official/blob/main/external_plugins/telegram/server.ts)
- **Aucune transcription** dans le plugin : aucune référence à un moteur speech-to-text dans `server.ts` (vérifié par recherche des termes transcri/whisper, 2026-09-28). — [server.ts](https://github.com/anthropics/claude-plugins-official/blob/main/external_plugins/telegram/server.ts)
- **Incohérence documentaire** : le README du plugin dit encore « there's no `download_attachment` tool… photos are downloaded eagerly » et ne documente que les photos, alors que le code expose `download_attachment` et gère vocaux/documents. Le README semble donc en retard sur le code. — [README](https://github.com/anthropics/claude-plugins-official/blob/main/external_plugins/telegram/README.md) vs [server.ts](https://github.com/anthropics/claude-plugins-official/blob/main/external_plugins/telegram/server.ts)
- **Évolution 2026** : issue #807 « feat(telegram): support voice messages and audio files » ouverte le **2026-03-20** (au lancement, les vocaux étaient « silently dropped ») — **fermée** ; la proposition laissait explicitement la transcription côté assistant (Whisper local ou API). — [GitHub anthropics/claude-plugins-official #807](https://github.com/anthropics/claude-plugins-official/issues/807)
- Issue #989 « Telegram plugin: add voice note support (Whisper transcription) », ouverte le **2026-03-25**, **toujours ouverte** au 2026-09-28, sans réponse de mainteneur visible ; elle demande aussi, en option, des réponses vocales (TTS). — [GitHub anthropics/claude-plugins-official #989](https://github.com/anthropics/claude-plugins-official/issues/989)
- Un projet communautaire (non officiel) ajoute la transcription des vocaux Telegram : « Voice Mode for Claude Code Channels ». — [GitHub marcus-cali/claude-voice-channels](https://github.com/marcus-cali/claude-voice-channels) (extrait de résultat de recherche ; mentionné seulement pour contexte, hors périmètre officiel)

**Ce que Claude peut renvoyer**
- Outils exposés : `reply` (texte + `files` en chemins absolus ; images .jpg/.png/.gif/.webp envoyées comme photos, autres types comme **documents** ; **max 50 Mo** par fichier ; découpage auto à 4096 caractères ; format `text` ou `markdownv2`), `react` (liste fixe d'emojis Telegram), `edit_message` (messages du bot uniquement ; « Edits don't trigger push notifications — when a long task completes, send a new reply »), `download_attachment`. — [server.ts](https://github.com/anthropics/claude-plugins-official/blob/main/external_plugins/telegram/server.ts) ; [README](https://github.com/anthropics/claude-plugins-official/blob/main/external_plugins/telegram/README.md)
- Pas d'historique : « Telegram's Bot API exposes neither message history nor search. The bot only sees messages as they arrive. » — [README](https://github.com/anthropics/claude-plugins-official/blob/main/external_plugins/telegram/README.md)
- Indicateur « typing… » automatique pendant le traitement. — [README](https://github.com/anthropics/claude-plugins-official/blob/main/external_plugins/telegram/README.md)

**Approbations à distance (permission relay)**
- Doc : « If Claude hits a permission prompt while you're away from the terminal, the session pauses until you respond. Channel servers that declare the permission relay capability can forward these prompts to you… For unattended use, `--dangerously-skip-permissions` bypasses most prompts, but only use it in environments you trust. » — [Anthropic, doc Channels](https://code.claude.com/docs/en/channels)
- Fonctionnement : terminal et téléphone restent actifs en parallèle, « Claude Code applies whichever answer arrives first » ; relais pour Bash/Write/Edit etc., mais **pas** pour les dialogues de confiance du projet ni de consentement des serveurs MCP (uniquement dans le terminal local). Identifiant de requête = 5 lettres minuscules (sans « l »). — [Anthropic, Channels reference, « Relay permission prompts »](https://code.claude.com/docs/en/channels-reference#relay-permission-prompts)
- Le plugin Telegram **déclare** la capacité `claude/channel/permission`, envoie la demande à tous les DM de l'allowlist avec boutons « See more », « ✅ Allow », « ❌ Deny », et accepte aussi une réponse texte `yes abcde` / `no abcde`. — [server.ts](https://github.com/anthropics/claude-plugins-official/blob/main/external_plugins/telegram/server.ts)
- Risque : « Anyone who can reply through the channel can approve or deny tool use in your session, so only allowlist senders you trust with that authority. » — [Anthropic, doc Channels, Security](https://code.claude.com/docs/en/channels#security)
- En mode non interactif `-p`, les questions à choix multiples et l'approbation de plan sont désactivées « so the session never stalls ». — [Anthropic, doc Channels](https://code.claude.com/docs/en/channels)

**Veille, fermeture, fonctionnement permanent**
- « Events only arrive while the session is open, so for an always-on setup you run Claude in a background process or persistent terminal. » — [Anthropic, doc Channels](https://code.claude.com/docs/en/channels)
- Le plugin interroge Telegram en **long polling** (un seul consommateur `getUpdates` par token) ; en cas de conflit 409 (session zombie ou deuxième Claude Code sur le même bot), il tente de tuer l'ancien poller puis **abandonne après 8 tentatives**. `TELEGRAM_STATE_DIR` permet plusieurs bots sur une machine. — [server.ts](https://github.com/anthropics/claude-plugins-official/blob/main/external_plugins/telegram/server.ts) ; [README](https://github.com/anthropics/claude-plugins-official/blob/main/external_plugins/telegram/README.md)
- Côté Telegram, les mises à jour non récupérées sont conservées sur le serveur « but they will not be kept longer than 24 hours ». — [Telegram, Bot API, « Getting updates »](https://core.telegram.org/bots/api) (extrait de résultat de recherche ; accès direct bloqué par le proxy)
- La doc Remote Control (même CLI) recommande `tmux` ou `screen` pour qu'une session survive à la déconnexion SSH d'une machine distante. — [Anthropic, doc Remote Control, Limitations](https://code.claude.com/docs/en/remote-control)

### Inferences
- **Vocal** : le fichier vocal (.oga/Opus) peut être récupéré par Claude, mais le plugin ne le transcrit pas ; il faudrait installer un outil de transcription local (ex. Whisper) ou une API tierce et demander à Claude (via CLAUDE.md/instructions) de l'utiliser. Cette brique n'est pas fournie par Anthropic. La reconnaissance du français dépendrait donc de l'outil tiers choisi. (Inférence : je n'ai pas trouvé de doc Anthropic indiquant que les modèles Claude acceptent directement de l'audio en entrée.)
- **Réponse vocale** : un fichier audio généré par un outil TTS tiers partirait comme « document » (pas comme bulle vocale native), puisque `reply` n'envoie que photos ou documents.
- **Veille/fermeture** : si le Mac/PC dort ou si le terminal est fermé, le plugin ne tourne plus ; d'après la règle de rétention Telegram (24 h) et l'absence d'option `drop_pending_updates` visible dans le code, les messages envoyés pendant une courte coupure devraient être récupérés au redémarrage — **non testé**.
- **VPS** : faire tourner `claude --channels …` dans tmux sur un serveur Linux allumé en permanence est cohérent avec la doc (« background process or persistent terminal »), mais : login claude.ai à faire sur le serveur, Bun à installer, et les approbations d'outils arriveront sur Telegram (ou il faut `--dangerously-skip-permissions`, déconseillé hors environnement de confiance).
- **Fiabilité** : vu la régression ouverte sur 2.1.283 (#97701), rester sur la version « stable » (2.1.274 au 16/09/2026) paraît prudent pour un usage « compagnon ».
- Les connecteurs Gmail/Calendar de claude.ai ne sont pas automatiquement disponibles dans une session CLI locale ; il faudrait des serveurs MCP configurés dans Claude Code (voir Gaps).

## Q3 — Claude Code « Remote Control » : fonctionnement, offres, prérequis, comparaison avec Channels

### Takeaway
Remote Control (`claude remote-control`, `claude --remote-control`, `/remote-control`) permet de piloter une session Claude Code **qui tourne sur votre ordinateur** depuis l'app mobile Claude (onglet Code) ou claude.ai/code : texte, photos et fichiers, notifications push, approbations. ## Q6 — « Routines » de Claude Code (planifiées / API / GitHub) : un bot Telegram externe pourrait-il déclencher une routine et récupérer le résultat ?

### Takeaway
Oui pour le **déclenchement** : chaque routine peut avoir un endpoint HTTP `/fire` (jeton Bearer) acceptant un champ `text` ; mais l'appel **ne renvoie que l'ID/URL de la session**, pas la réponse. Pour que le résultat revienne dans Telegram, la routine elle-même devrait appeler l'API Telegram (ce qui exige d'autoriser le domaine dans l'environnement cloud et de stocker le token du bot). Research preview, Pro/Max/Team/Enterprise, quota quotidien de runs, intervalle planifié minimum 1 h — et le bot Telegram intermédiaire serait un développement non officiel.

### Cited Findings
- « Routines are in research preview. Behavior, limits, and the API surface may change. » Une routine = prompt + un ou plusieurs dépôts + connecteurs, exécutée sur l'infrastructure cloud d'Anthropic, « so they keep working when your laptop is closed » ; déclencheurs : planifié, API, GitHub ; offres : **Pro, Max, Team, Enterprise** ; gestion sur claude.ai/code/routines ou `/schedule` en CLI. — [Anthropic, doc « Automate work with routines », non datée, consultée le 2026-09-28](https://code.claude.com/docs/en/routines)
- API : `POST https://api.anthropic.com/v1/claude_code/routines/<id>/fire` avec `Authorization: Bearer …`, en-têtes `anthropic-beta: experimental-cc-routine-2026-04-01` et `anthropic-version: 2023-06-01`, corps `{"text": "…"}` ; réponse : `{"type":"routine_fire","claude_code_session_id":…,"claude_code_session_url":…}` — « Open the session URL in a browser to watch the run ». — [Anthropic, doc Routines, « Trigger a routine »](https://code.claude.com/docs/en/routines#trigger-a-routine)
- Le `text` arrive enveloppé dans un bloc `<routine-fire-payload>` marqué comme **donnée non fiable** : le prompt de la routine doit explicitement dire d'agir sur ce contenu. — [Doc Routines](https://code.claude.com/docs/en/routines)
- « The `/fire` endpoint is available to claude.ai users only and is not part of the Claude Platform API surface. » Jetons créés uniquement depuis le web (pas via CLI). — [Doc Routines](https://code.claude.com/docs/en/routines)
- Les routines tournent sans demander d'autorisation (pas de sélecteur de mode de permission) et utilisent tous les outils des connecteurs inclus, « including writes, without asking for permission » ; les actions apparaissent sous votre identité. — [Doc Routines](https://code.claude.com/docs/en/routines)
- Réseau : l'environnement « Default » (accès « Trusted ») n'autorise qu'une allowlist de domaines ; les autres hôtes échouent en 403 `host_not_allowed` ; les connecteurs passent par les serveurs d'Anthropic ; pour joindre d'autres domaines, passer l'environnement en « Custom » ou « Full ». — [Doc Routines, « Environments and network access »](https://code.claude.com/docs/en/routines#environments-and-network-access)
- Limites : quota quotidien de runs par compte (valeur affichée sur claude.ai/code/routines, non publiée dans la doc) ; les runs one-off ne comptent pas ; intervalle minimum d'une planification = **1 heure** ; événements GitHub plafonnés par heure pendant la preview ; au-delà, crédits d'usage payants possibles. — [Doc Routines, « Usage and limits »](https://code.claude.com/docs/en/routines#usage-and-limits)
- `/schedule` requiert un login claude.ai (pas de clé API Console). — [Doc Routines, Troubleshooting](https://code.claude.com/docs/en/routines#troubleshooting)

### Inferences
- Montage possible (non officiel) : bot Telegram auto-hébergé → transcription éventuelle du vocal → `POST /fire` avec le texte → la routine traite (connecteurs Gmail/Calendar) → la routine envoie la réponse via `api.telegram.org` (domaine à autoriser + token du bot stocké comme variable/credential). Latence : démarrage d'une session cloud complète à chaque message ; aucune continuité de conversation entre deux `fire` (chaque appel crée une nouvelle session).

## Q8 — Existe-t-il une intégration officielle de claude.ai avec Telegram ou WhatsApp (bot, connecteur) ?

### Takeaway
Non : au 28/09/2026, je n'ai trouvé **aucun bot ni connecteur officiel claude.ai pour Telegram ou WhatsApp**. La seule intégration Telegram officielle est le **plugin Channels de Claude Code** (pont local, research preview). Côté WhatsApp, Meta interdit depuis le 15 janvier 2026 les chatbots IA « généralistes » sur l'API WhatsApp Business, ce qui rend peu probable un bot Claude officiel sur WhatsApp. Les intégrations Telegram/WhatsApp trouvées en ligne sont des services tiers (Make, Albato, Integrately…).

### Cited Findings
- Les canaux officiels listés par Anthropic sont Telegram, Discord et iMessage (plugins Claude Code) + fakechat ; aucune mention de WhatsApp. — [Anthropic, doc Channels](https://code.claude.com/docs/en/channels)
