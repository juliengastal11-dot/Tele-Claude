# Alternatives légères / orientées sécurité à OpenClaw pour un compagnon Telegram basé sur Claude (état au 28 septembre 2026)

> Périmètre : frameworks d'agents personnels auto-hébergeables « de type claw » utilisables avec Claude et Telegram (hors OpenClaw lui-même et hors simples ponts Telegram↔Claude Code, couverts par d'autres chercheurs). Les métriques GitHub (étoiles, forks, commits, releases) ont été relevées le **2026-09-28** sur les pages publiques GitHub. Plusieurs domaines (hermes-agent.nousresearch.com, nanoclaw.dev, ironclaw.com, docs.ironclaw.com, nanobot.wiki, hostinger.com, venturebeat.com, thenewstack.io, techradar.com, news.ycombinator.com, labs.cloudsecurityalliance.org, app.opencve.io, mindstudio.ai, shelldex.com) étaient bloqués par le proxy réseau de cette session : les informations qui en proviennent sont issues d'extraits de moteur de recherche et sont signalées comme telles.

## Q0 — Synthèse comparative : quel socle pour un compagnon Telegram (texte + notes vocales) sûr et maintenable ?

### Takeaway
Au 28/09/2026, aucun candidat ne réunit à la fois isolation forte, vocal Telegram natif, Gmail/Agenda prêts à l'emploi et installation simple pour un non-développeur. **Hermes Agent** est le plus complet (STT + TTS Telegram natifs, liste blanche refusant tout par défaut, offre managée chez Hostinger), mais c'est aussi le plus gros et le plus exposé (48 avis de sécurité dans la base GitHub). **NanoClaw** a la meilleure isolation (conteneurs + coffre d'identifiants) et une société financée derrière lui, mais le vocal passe par des skills communautaires. **IronClaw** a l'architecture « zero-trust » la plus poussée et très peu de CVE, mais le vocal n'est pas documenté et sa communauté est plus petite. **nanobot** est un compromis léger (vocal via Groq natif, canal e-mail, MCP avec OAuth, documentation en français). À écarter : **Moltworker** (preuve de concept sans commit depuis le 29/03/2026), **TinyAGI/TinyClaw** (sans commit depuis le 30/03/2026) et **PicoClaw** en production (le projet lui-même dit « Do not deploy to production before v1.0 »).

### Inferences
- **Chemin le plus court pour le vocal Telegram** (recevoir des notes vocales et répondre par la voix) : Hermes Agent. C'est le seul candidat qui documente nativement et de bout en bout la transcription automatique des notes vocales Telegram et les réponses en bulles vocales. Contreparties : un rythme de releases très rapide (5 releases en septembre 2026, chacune regroupant des centaines à ~1 800 PR) et un grand nombre de CVE. Il faut donc des mises à jour fréquentes et l'utilisation d'un backend Docker.
- **Priorité à la sécurité et à un code auditable** : NanoClaw (isolation par conteneurs + coffre d'identifiants, entreprise pérenne) ou IronClaw (sandbox WASM + injection d'identifiants, peu de CVE). Pour les deux, le vocal Telegram exigera un ajout : un skill communautaire pour NanoClaw, un ajout non vérifié pour IronClaw.
- **Compromis léger et polyvalent** : nanobot. Transcription native Groq/OpenAI, canal e-mail IMAP/SMTP, MCP avec OAuth (exemple Notion), documentation en français. Il faut impérativement une version ≥0.3.0 et activer `restrictToWorkspace` + la sandbox.
- **Pour Claude, dans tous les cas** : utiliser une **clé API Anthropic (Console)**. C'est le seul mode explicitement autorisé sans ambiguïté pour un outil tiers (voir Q2).
- Le nombre de CVE mesure autant la popularité (et le dépôt automatique d'avis par des CNA comme VulDB) que la qualité intrinsèque : Hermes, avec ~250k étoiles, est beaucoup plus scruté qu'IronClaw (12,6k).

### Gaps
- Aucun audit de sécurité indépendant publié et complet n'a été trouvé pour aucun des candidats (voir Q5).
- Le coût mensuel réel (tokens Claude + STT + hébergement) pour l'usage visé n'a pas été chiffré.
- La conformité RGPD et la localisation des données des offres managées n'ont pas été vérifiées.

## Q2 — Utilisation de Claude et compatibilité avec les conditions d'Anthropic

### Takeaway
La page juridique de Claude Code (consultée le 2026-09-28) est claire : les développeurs de produits utilisant l'Agent SDK doivent passer par une **clé API**, et l'OAuth des abonnements est réservé à « ordinary use of Claude Code and other native Anthropic applications ». La politique d'usage des abonnements Pro/Max dans des outils tiers a toutefois fluctué en 2026 : coupure le 4 avril, revirement le 13 mai, pause du crédit séparé le 15 juin, puis un e-mail du 16 juin indiquant que l'usage tiers continue « exactly as it did before ». **Conclusion : la clé API Anthropic est la seule option durablement sûre.** Hermes et ZeroClaw proposent aussi des chemins via jeton d'abonnement, et TinyAGI s'appuie sur la CLI Claude Code.

### Cited Findings
**Règles d'Anthropic (texte officiel en vigueur au 2026-09-28)**
- « OAuth authentication is intended exclusively for purchasers of Claude Free, Pro, Max, Team, and Enterprise subscription plans and is designed to support ordinary use of Claude Code and other native Anthropic applications. » — [Anthropic, Claude Code Docs « Legal and compliance », consulté le 2026-09-28](https://code.claude.com/docs/en/legal-and-compliance)
- « Developers building products or services that interact with Claude's capabilities, including those using the Agent SDK, should use API key authentication through Claude Console or a supported cloud provider. Anthropic does not permit third-party developers to offer Claude.ai login into their own applications, or to route requests through Free, Pro, or Max plan credentials on behalf of their users. » Les développeurs ne peuvent pas non plus « collect, store, or intermediate Claude.ai credentials or session tokens » — [même page](https://code.claude.com/docs/en/legal-and-compliance)
- La même page ne restreint pas la gestion par le client de ses propres clés API, « provided the resulting usage is billed to the key owner ». Elle n'empêche pas non plus un utilisateur de se connecter au binaire Claude Code non modifié avec son propre abonnement. Elle ajoute : « Advertised usage limits for Pro and Max plans assume ordinary, individual usage of Claude Code and the Agent SDK » et « Anthropic reserves the right to take measures to enforce these restrictions and may do so without prior notice. » — [même page](https://code.claude.com/docs/en/legal-and-compliance)

## Q3 — Support de Telegram : installation et contrôle d'accès

### Takeaway
Telegram est natif dans nanobot, PicoClaw, Hermes, ZeroClaw et TinyAGI. Chez NanoClaw, il s'ajoute par le skill `/add-telegram` ; chez IronClaw, c'est une extension WASM installée depuis l'interface web. Les comportements par défaut de sécurité diffèrent fortement. Hermes **refuse tout le monde** sans liste blanche, nanobot bascule en **mode appairage**, et NanoClaw impose un **appairage par code**. PicoClaw, lui, **autorise tout le monde** si `allow_from` est vide : c'est un piège pour un non-développeur.

### Cited Findings
- **Hermes Agent** : jeton via @BotFather, puis `hermes gateway setup` et `hermes gateway`. Le tableau de bord et l'application de bureau proposent un bouton « Create with QR ». « Hermes Agent uses numeric Telegram user IDs to control access » via `TELEGRAM_ALLOWED_USERS` ; « Without it, the gateway denies all users by default as a safety measure ». Variables supplémentaires : `TELEGRAM_GROUP_ALLOWED_USERS` et `TELEGRAM_GROUP_ALLOWED_CHATS`. Avertissement sur le mode webhook avec serveur Bot API local : « Anyone who can reach the port can fully control your bot » — [docs Telegram Hermes (dépôt GitHub)](https://github.com/NousResearch/hermes-agent/blob/main/website/docs/user-guide/messaging/telegram.md). La v0.21.2 (2026-09-11) a ajouté « Telegram quick setup with QR ported from the dashboard » — [Releases Hermes](https://github.com/NousResearch/hermes-agent/releases)
- **NanoClaw** : skill `/add-telegram` (jeton @BotFather). « Telegram tokens carry no user binding, so the agent proves you own the chat with a one-time pairing handshake: it issues a 6-digit code ». Les groupes se connectent via `/connect_group`, réservé aux propriétaires et administrateurs. Limite : « supports-threads: no » — [SKILL.md add-telegram](https://raw.githubusercontent.com/nanocoai/nanoclaw/main/.claude/skills/add-telegram/SKILL.md). Canaux installés « on demand with `/add-<channel>` skills » (WhatsApp, Telegram, Discord, Slack, Teams, iMessage, Matrix, Google Chat, Webex, e-mail via Resend…) — [README NanoClaw](https://raw.githubusercontent.com/qwibitai/nanoclaw/main/README.md)
- **nanobot** : champs `token` (à passer par variable d'environnement) et `allowFrom`. « When `allowFrom` is omitted, the channel enters pairing-only mode where unapproved users receive a pairing code. Setting `allowFrom: ["*"]` allows everyone. » — [docs/configuration.md nanobot](https://github.com/HKUDS/nanobot/blob/main/docs/configuration.md)
- **PicoClaw** : jeton @BotFather, liste `allow_from` (identifiants via @userinfobot). Quand `allow_from` est vide, « all users are allowed » — [docs/channels/telegram PicoClaw](https://github.com/sipeed/picoclaw/blob/main/docs/channels/telegram/README.md)
- **IronClaw** : « Channels such as Slack and Telegram have no configuration-file settings and no CLI enablement key: install the extension and complete its setup on the WebUI Extensions page » — [README IronClaw](https://raw.githubusercontent.com/nearai/ironclaw/main/README.md). La 1.3.0 (2026-08-19) permet de « Pair a personal Telegram account with the bot channel so the agent can read conversations » — [Releases IronClaw](https://github.com/nearai/ironclaw/releases)
- **ZeroClaw** : canal Telegram parmi plus de 30 canaux. Accès contrôlé par `allowed_users` (`["*"]` pour tout le monde, ou une liste d'identifiants) — [tutoriel LumaDock (date non vérifiée)](https://lumadock.com/tutorials/zeroclaw-telegram-bot-setup) (extrait de recherche). La v0.8.5 (2026-09-05) ajoute « debounce, poll and interactive-reply events » et des « structured QR-login lifecycle events » — [Releases ZeroClaw](https://github.com/zeroclaw-labs/zeroclaw/releases). Le README revendique « pairing, strict sandboxing, explicit allowlists, workspace scoping » — [GitHub ZeroClaw](https://github.com/zeroclaw-labs/zeroclaw)
- **TinyAGI** : Telegram intégré (BotFather, `/newbot`). « First message from unknown sender: TinyAGI generates a code and sends approval instructions » ; « channel clients apply sender pairing allowlist checks » — [README TinyAGI](https://github.com/TinyAGI/tinyagi)
- **Moltworker** : secret `TELEGRAM_BOT_TOKEN` à définir avant le déploiement. L'interface de contrôle est protégée par Cloudflare Access, un jeton de passerelle et l'appairage d'appareil via `/_admin/` — [README Moltworker](https://github.com/cloudflare/moltworker)

### Inferences
- Pour un non-développeur, Hermes (refus par défaut + QR) et NanoClaw (appairage à 6 chiffres) offrent les réglages par défaut les plus sûrs. Avec PicoClaw, un oubli de configuration ouvre le bot à n'importe qui.
- L'option IronClaw 1.3.0 (« read conversations » d'un compte Telegram personnel) élargit fortement ce que l'agent voit. Elle est à éviter pour un usage professionnel sans analyse de risque.

### Gaps
- Détails de l'appairage et de la liste blanche Telegram d'IronClaw : docs.ironclaw.com inaccessible, donc non vérifiés.
- Comportement par défaut exact de ZeroClaw quand `allowed_users` est vide : non vérifié.
- Un extrait de recherche (source non identifiée avec certitude) indiquait pour nanobot « Leave empty to allow all users ». La documentation actuelle décrit un mode appairage. Le comportement peut donc dépendre de la version et reste à vérifier sur la version installée.

## Q4 — Notes vocales Telegram : transcription (STT) et réponses vocales (TTS)

### Takeaway
**Hermes Agent** est le seul à documenter nativement la chaîne complète : transcription automatique (faster-whisper local sans clé, Groq ou OpenAI) et réponses en bulles vocales Telegram (Edge TTS gratuit, OpenAI, ElevenLabs). **nanobot** transcrit nativement (Groq par défaut, OpenAI, OpenRouter, AssemblyAI…) mais le TTS n'est pas documenté. **PicoClaw** annonce la transcription. Chez **ZeroClaw**, la transcription Telegram a longtemps manqué et doit être testée. **NanoClaw** n'a pas de skill vocal officiel (skills communautaires seulement). Pour **IronClaw**, rien n'est documenté.

### Cited Findings
- **Hermes Agent** : « Voice messages you send on Telegram are automatically transcribed by Hermes's configured STT provider and injected as text into the conversation ». Fournisseurs : `local` (faster-whisper, « no API key required »), `groq` (`GROQ_API_KEY`), `openai`. En sortie : « delivered as native Telegram voice bubbles ». - **PicoClaw** : le canal Telegram « supports… voice transcription » (renvoi vers le guide des fournisseurs) — [docs Telegram PicoClaw](https://github.com/sipeed/picoclaw/blob/main/docs/channels/telegram/README.md). La documentation en ligne mentionne Whisper via Groq — [docs.picoclaw.io, Telegram](https://docs.picoclaw.io/docs/channels/telegram/) (extrait de recherche). Le TTS n'est pas mentionné

Une infrastructure STT existe (Groq, OpenAI, Deepgram, AssemblyAI) mais n'était alors branchée que sur Slack et Discord. ### Inferences
- Pour la confidentialité des notes vocales (données d'affaires), l'option STT locale de Hermes (faster-whisper) évite d'envoyer l'audio à un tiers. Groq et OpenAI impliquent un transfert vers un fournisseur américain.

- Vocal Telegram d'IronClaw et fonctionnement effectif du vocal Telegram de ZeroClaw en v0.8.5 : non vérifiés.

## Q5 — Modèle de sécurité, vulnérabilités connues (CVE) et audits

### Takeaway
Sur le papier, **IronClaw** (sandbox WASM par capacités, secrets injectés à la frontière, liste blanche d'endpoints) et **NanoClaw** (conteneurs, identifiants jamais dans le conteneur) ont les modèles les plus robustes. **Hermes** reconnaît lui-même que « the only security boundary against an adversarial LLM is the operating system » et cumule 48 avis GitHub en 2026 (dont des RCE et une faille critique de chaîne d'approvisionnement). **nanobot** et **PicoClaw** ont connu des injections de commandes et des SSRF en 2026, et PicoClaw déconseille la production avant la v1.0. Aucun audit indépendant publié n'a été trouvé.

### Cited Findings
**NanoClaw**
- « Agents run in Linux containers and they can only see what's explicitly mounted ». « Credentials never enter the container — outbound API requests route through the installed credential gateway » (OneCLI Agent Vault par défaut) — [README NanoClaw](https://raw.githubusercontent.com/qwibitai/nanoclaw/main/README.md). La v2.4.0 (2026-09-23) ajoute Iron Proxy comme passerelle alternative — [releases.atom NanoClaw](https://github.com/nanocoai/nanoclaw/releases.atom)
- 10 avis dans la GitHub Advisory DB. Les plus graves : CVE-2026-7875 (**critique**, 2026-05-06, « Host/container filesystem boundary vulnerability »), CVE-2026-56402 (**haute**, 2026-06-23, élévation de privilèges avant 2.1.17), CVE-2026-56692/56693/56694 (moyennes, 2026-06-23 : symlink dans forwardAttachedFiles, élévation via create_agent, élévation via channel-registration). Plus récent : CVE-2026-90807 (faible, 2026-09-14, « up to 2.1.17 ») — [GitHub Advisory DB « nanoclaw »](https://github.com/advisories?query=nanoclaw)
- CVE-2026-7875 : CVSS 3.1 de 8,8. NanoClaw ≤1.2.0 permettait à un conteneur compromis ou victime d'injection de prompt de lire des fichiers de l'hôte hors du répertoire outbox, voire de provoquer des suppressions récursives — [CyberStrike, CVE-2026-7875](https://cyberstrike.io/cve/CVE-2026-7875/) (extrait de recherche). CVE-2026-56693 : CVSS 6,8, versions antérieures à 2.1.17 — [OpenCVE](https://app.opencve.io/cve/CVE-2026-56693) (extrait de recherche)

**PicoClaw**

- TinyAGI : aucune sandbox, seulement des espaces de travail d'agents isolés et l'appairage des expéditeurs — [README TinyAGI](https://github.com/TinyAGI/tinyagi)

### Inferences
- Pour un compagnon qui lit des e-mails (vecteur classique d'injection de prompt), la combinaison la plus défendable est un agent dont les outils tournent dans une sandbox OS ou WASM **et** dont les identifiants ne sont jamais exposés au modèle. NanoClaw et IronClaw sont les seuls à en faire leur argument central.
- Le rythme de Hermes (des milliers de PR par mois) et son volume de CVE imposent des mises à jour quasi hebdomadaires, difficiles à assurer pour un non-développeur sans offre managée.
- Beaucoup d'avis « faibles » (PicoClaw, Hermes) proviennent de dépôts automatiques par VulDB. Ils signalent une forte exposition, pas forcément un risque critique.

### Gaps

## Q7 — Installation, hébergement et empreinte

### Takeaway
PicoClaw et ZeroClaw visent le matériel minimal (binaire unique, quelques Mo de RAM, cartes à ~10 $). nanobot est un simple paquet Python. NanoClaw exige Docker, Node 22+ et Claude Code, mais fournit un script qui installe tout. Hermes s'installe en une ligne et propose un tableau de bord et une appli de bureau. IronClaw est le plus lourd (Rust, PostgreSQL). Moltworker impose Cloudflare Workers payant (~34,50 $/mois estimés).

### Cited Findings
- **NanoClaw** : « macOS or Linux (Windows via WSL2), Node.js 22+ and pnpm 10+, Docker Desktop or Engine ». `bash nanoclaw.sh` « walks you from a fresh machine to a named agent you can message » et « installs Node, pnpm, and Docker if missing ». Claude Code est utilisé pour `/customize`, `/debug` et l'installation de skills — [GitHub NanoClaw](https://github.com/qwibitai/nanoclaw) ; [README](https://raw.githubusercontent.com/qwibitai/nanoclaw/main/README.md)
- **nanobot** : Python 3.11+. Installation via uv, pip, installeur en une commande (macOS, Linux, Windows) ou Docker. Interfaces WebUI, CLI et messageries — [GitHub nanobot](https://github.com/HKUDS/nanobot) ; [README](https://raw.githubusercontent.com/HKUDS/nanobot/main/README.md)
- **PicoClaw** : « Core memory footprint <10MB — 99% smaller than OpenClaw », tourne sur du matériel à 10 $, « Boots in <1s even on a 0.6GHz single-core processor ». Précision : « Recent builds may use 10-20MB due to rapid PR merges ». Binaires précompilés, Docker Compose, APK Android. Architectures RISC-V, ARM, MIPS et x86 (LicheeRV-Nano, Raspberry Pi, MaixCAM…) — [GitHub PicoClaw](https://github.com/sipeed/picoclaw)
- **ZeroClaw** : script shell Unix, binaire PowerShell pour Windows, Docker, NixOS, compilation depuis les sources — [GitHub ZeroClaw](https://github.com/zeroclaw-labs/zeroclaw). Le README consulté ne chiffre pas la taille du binaire ni la RAM. Des comparatifs tiers évoquent environ 8,8 Mo de binaire et moins de 5 Mo de RAM (source exacte non vérifiée)
- **IronClaw** : compilation depuis les sources avec « Rust 1.96+ and Node.js 22+ with Corepack/pnpm ». Le README met en avant « PostgreSQL vs SQLite - Production-ready persistence ». Onboarding : choix du fournisseur puis saisie de la clé API — [README IronClaw](https://raw.githubusercontent.com/nearai/ironclaw/main/README.md)
- **Hermes Agent** : une ligne `curl -fsSL https://hermes-agent.nousresearch.com/install.sh | bash` (Linux, macOS, WSL2), ou PowerShell sous Windows. Dépendances installées par le script : Python, Node.js, ripgrep, FFmpeg — [GitHub Hermes](https://github.com/NousResearch/hermes-agent). Tableau de bord web et application de bureau (page Telegram avec « Create with QR ») — [docs Telegram Hermes](https://github.com/NousResearch/hermes-agent/blob/main/website/docs/user-guide/messaging/telegram.md)
- **Moltworker** : « Cloudflare Workers Paid Plan: $5 USD/month » obligatoire. Coût total estimé « ~$34.50/month » (abonnement + mémoire, CPU et disque provisionnés), hors coûts Claude — [README Moltworker](https://github.com/cloudflare/moltworker)
- **TinyAGI** : Node.js v18+, macOS, Linux ou Windows (WSL2), Claude Code CLI requis — [README TinyAGI](https://github.com/TinyAGI/tinyagi)

### Inferences
- Pour un non-développeur en France, un petit VPS Linux européen avec Docker est la cible la plus polyvalente. Il couvre NanoClaw (Docker requis), Hermes (backend Docker recommandé), nanobot et ZeroClaw. Un Raspberry Pi suffit pour PicoClaw ou ZeroClaw, mais leur maturité sécurité est moindre.
- La dépendance de NanoClaw à Claude Code pour la personnalisation est à double tranchant. Elle permet de personnaliser en langage naturel, mais chaque personnalisation modifie votre propre fork (maintenance à long terme).

### Gaps
- Empreinte mémoire mesurée de NanoClaw, Hermes, nanobot et IronClaw en fonctionnement : non vérifiée.
- Temps d'installation réel pour un non-développeur : aucune source indépendante fiable trouvée.

### Takeaway
